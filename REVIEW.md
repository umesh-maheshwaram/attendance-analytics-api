# REVIEW.md

Defects found in the starter `app/main.py`, all fixed in the submitted file. Shift: 09:30 - 18:30 IST unless noted.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Builds the shift start with `punch_in.replace(hour=h, minute=m)`. `punch_in` is a naive/UTC datetime, so the shift start is taken in UTC and on the wrong calendar day near midnight. IST is never used. | Punch in at 10:05 IST on a UTC server: the "shift start" is 09:30 UTC (15:00 IST), so a 35-minute-late punch-in gets late = 0. | Shift start is built as an aware IST datetime for the attendance date (`shift_window`), and the punch-in is compared to it as an aware instant. |
| 2 | `compute_late_minutes` | Grace rule is wrong. It floors to whole minutes first and then tests `> 10`, so 09:40:01 gives `int(10.01) = 10`, which is not `> 10`, so late = 0. R2 says strictly more than 10:00 is late. | 09:40:01 must give 10, the starter gives 0. | Compare in seconds (`seconds > 600`), then floor to minutes. |
| 3 | `compute_late_minutes` | No overnight handling and no truncation to whole seconds. | 22:00-06:00 shift, punch-in at 02:00 belongs to the previous day's shift. Also 09:40:00.900 must count as 09:40:00. | `attendance_date` applies R1 (previous day when before `shift_end` on an overnight shift). `from_ms` truncates instants to whole seconds before anything else. |
| 4 | `compute_work_hours` | Uses `round(x / 3600, 2)`: binary float, banker's rounding. R4 wants half-up. | 9630 s = 2.675 h; `round(2.675, 2)` returns 2.67, expected 2.68. | Exact `Decimal(seconds) / 3600`, quantized with `ROUND_HALF_UP`. |
| 5 | `compute_overtime` | No 30-minute minimum (R3), so 10 minutes after shift end gives 10. Shift end is always put on the record's date, so overnight shifts (end on the next day) give hugely negative or zero results. `date_str` is taken from the punch date, not the attendance date. | Out at 18:40 -> starter returns 10, expected 0. 22:00-06:00 shift out at 06:40 -> expected 40. | `shift_window` returns the real shift end (next day for overnight shifts); overtime is floored minutes, kept only when >= 30. |
| 6 | `EmployeeIn` | No validation at all. Bad `emp_code`, email, shift format, impossible `joined_on`, or `shift_start == shift_end` are all stored. Bad shift strings later crash `split(":")` in punch-in (500). | `POST /employees` with `"shift_start": "9.30"` returns 201, then every punch-in for that employee returns 500. | Pydantic patterns/lengths from the contract, calendar-date validator, `shift_start != shift_end` validator, all returning 422. |
| 7 | `create_employee` | Check-then-insert (`find_one` then `insert_one`) with no unique index: concurrent creates all return 201 and produce duplicate `emp_code`s. `created_at` is a naive local `datetime.now()` and is returned as a datetime string instead of epoch ms. | 10 parallel POSTs with one `emp_code` -> several 201s. | Unique index on `emp_code`; insert and catch `DuplicateKeyError` -> 409. `created_at` is stored as UTC and returned as epoch ms. |
| 8 | `list_employees` | `skip = page * page_size` skips the whole first page. `total` is `count_documents({})`, ignoring the department filter. No sort, no limits on `page` / `page_size` (0, negative or huge values reach MongoDB and return 500 or abuse memory). | `?page=1` returns the second page; `?department=HR` reports the total of all employees. | `skip = (page - 1) * page_size`, `total` counts the filtered set, sort by `emp_code`, `Query(ge=1)`, `page_size` 1..100. |
| 9 | `punch_in` | Unknown employee: `emp` is `None`, then `emp["shift_start"]` raises `TypeError` -> 500. | `POST /attendance/punch-in {"emp_code": "NOPE"}`. | Explicit 404. |
| 10 | `punch_in` | Time handling: `datetime.fromtimestamp(ms / 1000)` is machine-local and naive; `ts.date()` is therefore the server's date, not the IST date (R1); microseconds are kept; `if body.punched_at` treats a value of 0 as "now"; floats and numeric strings are accepted as `int`. | Server in UTC, punch-in at 00:30 IST gets the previous day's date. Body `{"punched_at": "1783312500000"}` returns 201. | `EpochMs` is a strict int in the contract range (seconds, floats, strings, booleans -> 422); conversion is UTC-aware; date comes from `attendance_date` (IST, overnight aware); seconds truncated. |
| 11 | `punch_in` | `status` is a free string. `ABSENT`, `LEAVE` or any text is accepted. | `{"status": "banana"}` -> 201. | `Literal["PRESENT", "WFH", "ON_DUTY"]`. |
| 12 | `punch_in` | Check-then-insert race and no unique index: two simultaneous punch-ins both pass the `find_one` and both insert. | Fire 10 parallel identical requests; more than one 201 and duplicate rows. | Unique index on (`emp_code`, `date`), a single `insert_one`, `DuplicateKeyError` -> 409. No read before write. |
| 13 | `punch_in`, `list_attendance` | Response leaks internal `id` (the ObjectId as a string) and returns raw datetimes instead of epoch-ms integers; legacy documents without `history`/`half_day` are returned as they are. | Response contains `"id": "66..."` and ISO-string timestamps. | `record_out` builds the contract shape: no id, ms integers, defaults for missing fields. |
| 14 | `list_attendance` | `find(q)` loads the whole matching collection into memory and sorts in Python. No index, so a collection scan on every call. Sort lacks the `emp_code` tiebreak. No validation of `page`, `page_size`, dates, `date_from > date_to`, or `status`. | 100k documents: seconds per request and large memory. `page_size=-5` slices from the end. | Filter built once, Mongo does `sort` / `skip` / `limit` on a compound index `(date -1, emp_code 1)`, `estimated_document_count` when unfiltered, validation -> 422. |
| 15 | `health` | Always returns ok, even when MongoDB is down. | Stop MongoDB: `/health` still 200. | Pings MongoDB, 503 on failure. |
| 16 | module setup | `MongoClient` default returns naive datetimes; no index creation at all; default 30 s server selection timeout; Mongo errors surface as 500. | Naive datetimes get interpreted as local time by `timestamp()`. | `tz_aware=True`, indexes created idempotently in the lifespan hook, 5 s timeout, `PyMongoError` -> 503. |

## Looked at and decided it was fine

* `IST = timezone(timedelta(hours=5, minutes=30))` is correct (no DST in IST).
* `load_dotenv()` does not override variables that are already in the environment, so real env vars win as required.
* `doc.pop("_id")` after `insert_one` is needed because PyMongo adds `_id` to the dict; the fix just builds the response explicitly instead.
* Using `skip`/`limit` for pagination is fine at this scale once the page offset is corrected; the trade-off for 100x data is in `DECISIONS.md`.
